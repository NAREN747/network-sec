Project Overview

A complete network security lab spanning design, analysis, configuration, and detection

Scope

  • 4 Course Outcomes (CO1–CO4)
  • Detection-only scope (prevention via router ACLs)
  • No inline WAF/IPS — router enforces policy
  • Unified demo runner: python run_demo.py

Environment

  • Cisco Packet Tracer 8.x (topology: Network_Security_Project.pkt)
  • Python 3.12+ with scapy, pyshark, pyyaml
  • Windows 11, MSYS2/bash terminal
  • Flat GitHub structure (main branch)

Execution Order

1
CO1 — Architecture — Foundation: IPs, VLANs, zone policy used by CO3/CO2
2
CO3 — Router Config — Builds lab topology; produces network CO2/CO4 run on
3
CO2 — Protocol Analysis — Runs traffic through CO3 topology, captures for CO4
4
CO4 — Threat Detection — Consumes CO2 captures + synthetic malicious PCAPs

Key Design Decisions

  • RoAS (Router-on-a-Stick) — Single router, one trunk, clear sub-interface mapping
  • TEST-NET-3 (203.0.113.0/24) — RFC 5737 reserved for documentation
  • Default-deny ACLs — Explicit permits only, mirrors Palo Alto/FortiGate logic
  • YAML signatures — Non-coders can tune rules without touching Python
  • JSONL output — SIEM-ready (ELK, Splunk, Loki compatible)

Security Principles

  • Default Deny — implicit deny every ACL
  • Least Privilege — only required ports/protocols
  • Containment — DMZ cannot initiate to LAN/MGMT
  • Management Isolation — MGMT only from admin host
  • No Direct Internet→LAN — all traffic terminates at DMZ
  • Stateful Inspection — established keyword for return traffic

ACL Implementation

  • ACL-INTERNET-IN/OUT — WAN (Gi0/1)
  • ACL-DMZ-IN/OUT — DMZ (Gi0/0.20)
  • ACL-LAN-IN/OUT — LAN (Gi0/0.10)
  • ACL-MGMT-IN/OUT — MGMT (Gi0/0.99)
  • ACL-VTY-IN — SSH only from 10.10.0.0/24

CO2: Protocol Stack Analysis — L2→L7 Breakdown

Single HTTP flow: PC (10.10.10.50:54321) → Web Server (10.10.20.10:80) via Router (10.10.10.1)

Layer 2 — Ethernet/ARP

  • Frame: Src/Dst MAC, EtherType 0x0800/0x0806
  • ARP Request: "Who has 10.10.10.1?"
  • ARP Reply: Gateway MAC resolution
  • FCS: CRC32 integrity

Layer 3 — IPv4

  • Version 4, IHL 5, TTL 64→63
  • Protocol 6 (TCP), DF flag set
  • Src: 10.10.10.50 → Dst: 10.10.20.10
  • Routing: 10.10.20.0/24 via Gi0/0.20

Layer 4 — TCP

  • 3-way handshake: SYN → SYN-ACK → ACK
  • Ephemeral 54321 ↔ Well-known 80
  • ISN randomized, MSS 1460
  • Window 64240, PSH+ACK for data

Layer 7 — HTTP/1.1

  • GET /index.html, Host header
  • Keep-alive, Accept-Encoding: gzip
  • 200 OK, Content-Length, ETag
  • Server: nginx/1.24.0 (info leak risk)

Encapsulation Flow

Application Data (HTML)
    ↓ HTTP Headers
TCP Segment (Port 54321→80, Seq/Ack, Flags)
    ↓ TCP Header
IP Packet (Src=10.10.10.50, Dst=10.10.20.10, TTL=64)
    ↓ IP Header
Ethernet Frame (Src=Client MAC, Dst=Gateway MAC, Type=0x0800)
    ↓ Ethernet Header + FCS
Physical Bits on Wire

Tools Used

  • tshark/tcpdump — capture
  • scapy — programmatic analysis
  • Wireshark — GUI inspection
  • protocol-stack/live-demo.py — reproducible generation

Deliverables

  • protocol-stack/analysis.md — full header breakdown with values
  • protocol-stack/pcap/http-flow.pcapng — captured traffic

CO4: Threat Detection Engine — Architecture

Python-based detection: stream reassembly + YAML signatures + behavioral anomalies + JSONL output

PacketCapture

  • Wraps pyshark/scapy
  • Live or offline (.pcap)
  • BPF filter support
  • PCAPNG compatible

PayloadExtractor

  • TCP stream reassembly
  • HTTP chunked encoding
  • URL decoding (evasion)
  • Ports: 80, 443, 8080, 8443

SignatureEngine

  • Loads signatures.yaml
  • Compiles regex (IGNORECASE|DOTALL)
  • Per-payload matching
  • Category filtering

AlertEmitter

  • JSON Lines (SIEM-ready)
  • STDOUT streaming
  • Severity: critical/high/medium/low/info
  • Deduplication by sig+IP+content

AnomalyDetector (Behavioral)

  • SYN Flood / Port Scan — >20 unique dst ports from same src in 5s
  • Port Sweep — >50 unique sources to same dst port in 10s
  • Regular Beaconing — 6+ connections, ±10% interval variance over 30min
  • DNS Tunneling — High query volume, long subdomains (>50 chars)

Performance Optimizations

  • Stream reassembly only for HTTP family ports
  • TLS payloads flagged tls_encrypted — no false positives
  • Bloom filter for seen flows (avoid re-processing)
  • Multi-decode: UTF-8 → latin-1 → ASCII → ignore

Output Format (JSONL)

{"timestamp":"2026-11-20T10:01:32","src_ip":"10.10.10.51","dst_ip":"10.10.20.10","src_port":54322,"dst_port":80,"protocol":"TCP","category":"xss","signature_id":"xss-script-tag","signature_name":"Script Tag Injection","severity":"high","description":"Classic ","packet_summary":"10.10.10.51:54322 -> 10.10.20.10:80"}
